# 成品视频提示词入口（统一旁白参考）

本入口沿用原 `metasocli-video-prompts` 的内容、图片和视频请求内启用 Context IR 的流程，仅增加下文的旁白判断、音频登记和引用；原入口不会自动启用这份旁白。用户只需调用本技能并提供完整提示词，默认旁白文件已在当前安装中配置。选择本技能授权本地整理、参考素材准备和音频绑定；包含 IR 的视频生成须有覆盖本次范围及此模式的明确授权。

完整读取用户指定的全部 UTF-8 TXT/Markdown。不要重新分镜、缩短台词或倒推剧本。DOCX/PDF 需由宿主先可靠提取并经用户任务范围认可；CLI 本版不直接解析这两种格式。提示词直接粘贴在消息中时，先完整保存为当前故事的 UTF-8 来源文件。

读取 [草稿契约](../../docs/INPUT_FORMAT.md)。选择 `kind: video-prompts`。分段 `start/end` 是规范文本的 UTF-16 范围，必须按序覆盖全部正文；用程序计算，不手抄长正文或哈希。`duration` 可填原始目标秒数，例如 `6.963`；程序自动向上取整为 H3 实际请求的 7 秒，并在计划保留原始目标。正常小数适配不逐段询问、不改原文、不裁剪成片；图片和旁白绑定流程保持不变。带旁白选择时使用 JSON 草稿导入。

按用户明确引用清单的顺序绑定素材；同名不同造型分配不同 assetId。没有明确来源的台词提及对象不自动认定为出镜素材。只有 `{{ref:assetId}}` 被技术渲染为按输入顺序编号的自然语言标签；姓名、普通“图1”、空白和其他正文不替换。旧节点标记必须先明确映射，不能直接发送。

统一分析全部素材，保存逐集图片交接请求：每个人物的固定造型、场景状态、关键连续性道具分别使用独立 assetId；只给实际出镜或明确需要该参考的段分配素材，不把一份全体人物合照绑定给每段。记录原文事实、生成设定、连续性、图片依赖和 requiredBySegments，具体结构见 [图片交接契约](../metasocli-reference-images/references/handoff-contract.md)。优先遵守用户明确指定的素材及引用。

调用 [参考图片 Skill](../metasocli-reference-images/SKILL.md) 第一阶段，将完整人物/场景/道具/首帧模板落实为完整配方，校验后原样写入导入草稿，不能先写几句简化配方再生图。CLI import 后执行该 Skill 第二阶段，复用准确 ready 素材，仅生成缺失必需项并正式登记。两阶段自动衔接，不要求用户另调图片技能或逐图批准。图片请求与图片依赖均排除 `kind: narration`；旁白录音继续由本入口单独登记，不交给生图工具。缺图不悄悄降级为纯文字，首帧不能与多参考图或旁白音频混用。仅缺少明确目标、无法解释的时长冲突或超出允许范围时报告准确段落；正常小数向上取整不是冲突，也不自动删减。

## 逐段、逐镜头判断旁白

完整阅读每段的镜头、说话主体、声音设计、台词和口型归属，判断哪些具体文字是叙述性画外旁白。字段名“台词/旁白”本身不足以证明是旁白；纯人物对白、画外角色说话、音乐、环境声和静默不自动归为旁白。人物不在画面内也不自动等于叙述者。确有歧义时定位原句及镜头，请用户澄清该处，可继续其余明确段落的准备。

- 含旁白的段：保持原有全部参考图，用一个 `narration` 对象绑定统一音频；`cues` 仅圈选该段原文中明确属于旁白的文字，排除混合段内的角色对白。用程序按原文计算 UTF-16 范围，不重抄或改写正文。
- 无旁白的段：`narration: null`，不添加旁白音频或旁白说明。新入口的每个已判断段都应显式记录对象或 null，避免遗漏；判断不明不记为无旁白。
- 多个旁白镜头共处一个段时，同一音频只绑定一次，记录多个有序、不重叠的原文范围。同一音频跨段复用。
- MP3 是通用声线示例，不用其录音台词匹配某一段，不把录音内容补入剧情，不将整条 MP3 当作该段的完整配音或后期铺轨。不固定套用 test34 的“所有31段都需要旁白”结论。
- 首帧和参考音频在 H3 中不能混用，遇到这种段明确报告；不擅自把首帧改成普通参考图，也不省略旁白要求。

将逐段判断（段 ID、是否有旁白、所选原句及镜头依据）保存为故事内的 `narration-review.json`，与生成计划一起供用户检查。它是本地分析记录，不是额外批准环节。

## 固定旁白音频与登记

当前安装的默认音频副本：`E:\metasocli\.local\narration\default.mp3`。

该文件来自用户明确提供的 `旁白.mp3`，SHA-256：`d58249d4f000181f30e33e1b821fca408329b4a58b6ed9b39c672eba5b7da947`。时长约 9.822 秒。副本属于此独立安装，不依赖 test34、LibTV 或桌面原文件；不随 Git/npm 分发。用户当前明确指定替换音频时使用其新文件并计算新哈希。默认文件缺失或哈希变化时明确报告并恢复指定文件，不搜索相似音频或偷偷换人声。

有需要旁白的段时，在草稿 `recipes` 中声明一次：

```json
{"assetId":"narrator-default","kind":"narration","prompt":"用户指定的统一画外旁白声线参考；仅参考音色、咬字、语气、节奏与情绪，不复述录音台词。","exactText":[],"dependencies":[]}
```

导入草稿后，通过本项目命令登记已有音频（只做本地校验和独立复制，不上传、不生成）：

```text
node E:\metasocli\dist\cli\main.js assets register --root <story> --id narrator-default --file E:\metasocli\.local\narration\default.mp3 --provenance user --expected-sha256 d58249d4f000181f30e33e1b821fca408329b4a58b6ed9b39c672eba5b7da947
```

不裁剪、变声、重采样或重新生成这份录音。音频支持 MP3、PCM/浮点 WAV，2–15 秒、单文件不超过 15 MiB，每段一个旁白参考。仅有纯对白/无声段时不必登记旁白资产。

## 计划、生成与恢复

后续使用 [剧本入口的公开命令与恢复规则](../metasocli/SKILL.md)，并完整读取 [当前 Context IR 流程](../../docs/INLINE_CONTEXT_IR_WORKFLOW.md)。新草稿段参数 `contextIr` 写 true，执行 `plan --root <story> --episode <id> --workflow h3-inline-ir`，确认全部计划段 `contextIr:true`。按剧本入口批次规则，将选定全部集和段离线冻结为一个 `batch plan --root <story> --episodes <有序集ID> --concurrency 4`；部分段用 `--selection <selection.json>`，不按标题重拆技术 episodeId，不按8段截断。展示 `plan.batchId`、哈希和总数/复用/活动/待提交数，默认停在视频提交前。用户授权当前范围及含 IR 的视频模式后，直接 `batch run --root <story> --batch <batchId> --confirm`，不逐段或每4段请求批准，也不先单独执行 context-ir 或 plan --from-context-ir。

最多4段占用生成名额，任一服务端终态验证并持久化后补下一段，task_id 不代表完成；最多2个独立下载，慢下载不堵塞补位。有旁白的段继续绑定原参考音频，没有旁白的段不添加音频，乱序完成不改变图序、cues、资产归属或输出路径。按用户明确集序、原段序提交；独立 IR 历史范围不明时使用显式选择，不自动把副本纳入 `--all-episodes`。

中断后 `batch status --root <story> --batch <batchId>` 只读记录；`batch resume --root <story> --batch <batchId>` 沿用原 ID 和授权，允许继续原范围内未提交段。旧 `resume --operation` 不创建新任务。复用合格成片，下载失败只恢复下载；未知创建保留占位并暂停新增，明确失败不自动重做，安全429仅在持久化预算内退避。多个新版入口共用安装名额，不能通过并开终端或换运行目录绕过。

计划应展示：原参考图顺序、旁白音频哈希、音频时长、各段旁白范围、最终提示词及模型参数。有旁白的请求会包含 `audio_url` / `role: reference_audio`，与图片共同进入 Metaso H3 多模态参考模式；没有 LibTV 节点、连线或旧 CLI。

CLI 保留原文，在基础渲染文本末尾另附旁白说明，随原图与音频一起发送到视频接口，并明确携带布尔值 `context_ir_enabled:true`：仅对圈选的叙述性画外旁白参考这份音色、咬字、语气、节奏与情绪；不照搬音频台词、不替代人物对白、不让画外旁白驱动人物口型。无需手工把说明拼回原始提示词。说明也计入长度上限。

提交前对照原始提示词、原 cues 提取的旁白句和完整请求文本核对：完整对白及说话人顺序、原参考图编号、旁白仅作用于指定画外叙述、角色对白声线和口型不被接管、没有新增不存在的音频或要求复述 MP3。冲突在提交前处理，不自动付费重跑。IR 在服务端视频请求内执行，没有独立增强文本可在生成前审阅，不能编造该审阅或服务器返回的 true。

原 cues 始终指向原始提示词，禁止覆盖源 prompt/hash。原始提示词、技术旁白说明、原图序与原音频共同送入视频请求，只在有旁白的段携带音频。旧 false 计划对原始集重新 plan，不能改写旧哈希或自动将 IR 副本集再增强。resume/status/download 只恢复原任务，不因接口响应缺少 context_ir_enabled 而重发。

音频缺失、内容变化或引用未校验时停止受影响的计划，不能只把“参考旁白”写进文字却不传音频。已提交任务仍凭原 taskId 恢复；音频后来变化也不能触发原任务重生成。离线校验不等于真实声线效果已验证。
