# metasoclitk

用户要求把明确集段换成已定稿的完整提示词时，先读并执行[指定段提示词一次替换](../../docs/PROMPT_REPLACEMENT.md)：沿用原集 ID/段 ID，一次本地调用核对文件哈希、执行一次 prompts replace 并核验回执；仅要求换稿时到此结束。此分支先于下面的图片授权、模板、全文导入、工作流及视频文档读取；不改资产图、配方、图序、时长或其他段正文，已有旁白只按新稿安全保留/映射原声音。被其他入口继承时不重复执行。用户同时明确要求视频或其他操作时，按用户指定的替换顺序完成各自固定入口，再进入对应流程并沿用其授权范围。

用户明确要求生成视频时，随原有说明同次读取安装根下可选的 `.local/video-execution-authorization.md`，按[本机视频授权](../../docs/VIDEO_EXECUTE.md#本机视频授权)用于原提交。需要选稿或换参考素材时，按[首次确认](../../docs/VIDEO_EXECUTE.md#改稿或换参考素材时的首次确认)只问尚待用户决定的事项。

用户说“把资产图换成这张”且已选定本机图片时，默认按[同 ID 纯换图判断](../metasocli-reference-images/references/selected-local-image.md)处理。目标唯一就沿用原资产 ID，即使选图已登记在另一个 ID 下，也在一次本地调用中核对选图 SHA-256、登记一次、校验并交付回执，到此结束。同时明确授权换图和指定段视频时，先登记再按新版清单冻结所选段。

当前正式 Story 的所选集段、完整提示词、参考图及旁白已就绪且用户要求视频时，直接使用[固定视频入口 video run](../../docs/VIDEO_EXECUTE.md#固定视频入口)，一次调用完成本地准备、范围核对、提交/查询/下载和交付；本分支先于下面的图片授权、模板、全文导入和图片工作流读取，被其他入口继承时不重复执行。已有准确 batchId 直接按原 ID 恢复。不要为此另做 import、assets list、doctor、图库/ZIP、全剧 TXT 或 current 指针。直接交付返回的正式文件路径和回执，不再复制或登记成片；仅用户明确要求音视频解码时加 --verify-av，视觉抽查另列结果。

只换图或只换稿时仍执行上面的单次本地入口并结束，video run 调用次数为0。同时明确要求换图、换稿和视频时，按用户顺序执行各一次原替换命令，逐份核验回执，再以最新正式 Story 调用一次 video run；可在同一宿主调用中顺序完成。任一步失败立即停，不自动撤销此前已成功的替换，报告已完成事项和视频尚未提交。runner 本身不代登记、改稿或导入。尚缺素材、未定稿、旁白归属不明或范围不明时，先走原流程补齐必要输入，不把它当作就绪视频。下文批次规则继续限定授权、未知保护和四名额调度。

开始执行就完整读取 [已有图片授权与提交上下文](../../docs/IMAGE_EXECUTION_AUTHORIZATION.md)，不要等到付费提交被拒绝后才读取。用户已要求的当前图片范围直接沿用已有发送授权，实际工具调用明确带上授权来源、目的地和冻结范围；正常审批仍适用。本入口的视频授权规则另行保留。

这是 `metasocli-video-prompts` 的独立资产图风格入口。保留原文导入、段落与素材对应、图片 API、登记、视频计划、生成和恢复流程；为新准备的 `character`、`scene`、`prop` 配方应用本技能的 jianc 通用设计板规则。运行所需规则已在本包内，不需要读取 jianc 项目、其原片、示例人物或已有图片。

## 安装目录与跨设备使用

以本正文所在的 `skills/metasoclitk/` 向上两级确定实际安装根 `INSTALL_ROOT`，核对该目录中的 `package.json` 包名为 `metasocli`，程序入口为 `INSTALL_ROOT/dist/cli/main.js`。正文及被引用文档中的 `E:\metasocli` 是源设备示例，全部适配为当前实际安装根；不要因为本机安装在 C/D 盘或其他目录而另外创建 E 盘目录。每份被引用文档的相对链接按该文档所在目录解析。

故事目录仍单独显式传 `--root`，不因升级移动或重建旧故事、凭据和运行账本。新设备无需存在 `E:\libcli` 或 jianc 项目；旧项目的只读保护仍有效。安装、升级与用户级入口说明见 [部署说明](../../docs/METASOCLITK_DEPLOYMENT.md)。

## 接入原流程

1. 完整读取同包 [成品视频提示词入口](../metasocli-video-prompts/SKILL.md)，按其处理完整输入、故事目录、分段、图序和生成授权。程序仍是本包 `dist/cli/main.js`，所有业务命令显式传 `--root <story>`。本技能不另建 CLI、账户、运行账本或生图接口。
2. 在编写任何图片配方和执行 import **之前**，读取 [参考图片流程](../metasocli-reference-images/SKILL.md) 以复用交接契约、API提交、登记和恢复步骤。该流程中人物、场景、道具的模板读取与配方组装步骤，在本入口完全替换为本技能 [统一视觉规则](references/visual-style.md) 和当前实际需要的新模板：
   - `character`：[人物五视图](references/character-board.md)。
   - `scene`：[场景空间设计板](references/scene-board.md)。
   - `prop`：[道具结构材质板](references/prop-board.md)。
   - `first_frame`：继续使用原 [单幅首帧规则](../metasocli-reference-images/references/first-frame.md)，不把多格设计板当作首帧。
3. 本入口新准备的人物、场景、道具配方只采用上述新模板的风格、布局及内容组织方法。不要执行共用图片技能要求读取旧三类类型模板的步骤，也不把旧模板或默认写实摄影描述拼入配方；共用技能保留的原文事实、资产身份、完整配方传递及技术校验规则继续适用。每项资产直接形成一份新模板配方并提交一次，不先按旧模板生成一张再转成新类型。用户当前明确指定的风格或素材优先。视频原文、人物身份和剧情事实保持原样，不向视频正文追加或替换美术风格。
4. 一项资产生成一份独立完整提示词。将本故事具体外观、完整板式、实际标题与资料、各视图标签、材质、光影和连续性要求展开，不只写“按 jianc 模板”。基础文本定稿后、保存哈希和交接之前，完整执行 [按 kind 追加原文](../metasocli-reference-images/references/denoise-policy.md)：以 entrySkill=metasoclitk 调用包内 append_asset_denoise.py compose/check，character/scene/prop 各只追加对应全文一次并放在末尾；这是共享技术尾段，jianc 三类模板仍完整使用，不叠加所继承入口的第二份。按原契约保存 request/recipe 并校验；将工具输出的完整 `prompt` 同时写入 `generationPrompt` 和草稿 `recipes[].prompt`，使用追加后的 recipeSha256。事实保留在 `sourceFacts`，生成设定在 `visualDescription` 中明确区分；不增加契约不支持的 JSON 字段。first_frame、旁白与旧配方/计划恢复不追加。
5. 收齐本次全部集/段的配方及交接，调用共用 images prepare/run/collect，再沿原图片流程使用 `api / gpt-image-2.5 / all-ready`。读取实际计划确认人物、场景、道具的默认请求尺寸为 `1920x1088`；若安装配置不同，为本次计划传入支持的显式 profile，不修改全局默认。当前用户明确更高规格时按原图片文档匹配实际 size。`built_in` 仅在用户明确选择时使用，已有真实参考图依赖按原顺序传入。缺少图片 Key 时继续离线准备与计划。
6. 原样执行原技能的首次图片保存、技术校验、正式登记及结果交接，不增加审美评分、OCR、自动重画或逐图批准。必要素材 ready 后，调用一次 `video run` 冻结所选段和整集父计划，已授权时同次加 `--confirm` 执行并交付，实际请求保持 `context_ir_enabled:true`。恢复、一次性重试与图片/视频阶段互斥均使用原正式入口。

## 授权、复用与旁白

- 选择本技能指定视觉风格，不增加付费范围。沿用已明确的图片供应商/范围授权；没有图片授权时停在图片计划。没有视频授权时停在视频提交前，当前范围已授权时按原流程继续。
- 已有 ready 资产按精确身份、原配方和真实哈希复用，用户指定图片不为套模板自动重画。用户明确要求将旧素材改为此风格时，依据原契约建立新资产 ID 并更新对应引用，保留旧配方、图片与任务；不能把不同风格的复用图说成此次新风格成图。
- 默认继承普通成品提示词入口，不自动附加统一旁白音频。已有明确音频绑定保留；用户明确要求使用已配置的统一旁白时，再读取 [旁白入口](../metasocli-video-prompts-旁白/SKILL.md)，照其判断、绑定和登记规则执行，同时继续采用这里的三类图片模板。
- 本技能用于新故事的内容来自当前输入，不复制 jianc 的姓名、金发银发、龙角、服装、场景、道具或其55/29/29数量。图片板式与目标审美可复用，具体生成效果仍以实际返回图片为准。

## 使用

```text
$metasoclitk
（这里粘贴完整的视频提示词，或指定提示词文件和故事目录）
```

默认准备本次需要的 jianc 风格资产图配方，并按原授权范围继续；不要求用户另外调用图片技能。只请求模板或提示词时交付对应文本，不自动生成。新技能不修改其他入口的模板或默认行为。

## 不同故事隔离与恢复

完整遵循 [项目隔离与冷切换](../../docs/PROJECT_ISOLATION.md)。不同故事的缺图、依赖等待、暂停、未知或目录异常不阻止本故事使用空余容量；同故事锁、阶段互斥、未知阻断和一次性重试规则保留。默认不要求 --accept-existing-unknown；旧确认仅保留审计身份，不扩大授权或重发未知。

图片保持 gpt-image-2.5 / all-ready / 有效600秒，配置的 concurrent/RPM 共享核验。视频保持 MiniMax-H3、context_ir_enabled:true，全机同 runtime 合计最多4个生成名额，项目 concurrency 为附加上限；1个外部未知留下3个空位，4个未知则新增视频等待，图片与原结果恢复仍可运行。不得删除旧未知、换 runtime 或伪造终态腾位。

images run/resume/retry 与 batch run/resume/retry 支持 --capacity-wait-ms 30000 --capacity-poll-ms 250。耗尽后保留原计划/批次授权和 operationId，按原 resume 继续；准确区分本项目未知、依赖未就绪、共享容量等待、同项目进程占锁和协调器损坏。视频批次只查询当前故事，其他故事由其自身恢复落盘终态，不自动跟随外部 GET。

升级先结束旧版生成进程，再统一切换构建和正文；活跃或不明旧全局锁不得抢占，不支持新旧二进制热混跑。原文、图序、时长适配及旁白归属不变；只有有旁白的段带原音频，普通入口不自动加旁白。默认授权停止点不变，本规则不新增任何付费授权。

## 固定图片工作流

完整读取并执行 [共用 prepare/run/collect 流程](../metasocli-reference-images/references/image-workflow.md)。API 图片先完成本入口必要的原文分析与完整配方，再用一次 `images prepare` 校验全部交接、逐集导入并冻结同一计划；沿用原授权执行 `images run --summary`，用 `images collect` 收集真实结果。已有正式计划直接复用或恢复，不强制补准备记录，不反复现场编写机械执行脚本。该接入不改变本入口模板、图片顺序、旁白判断或音频登记；未知和部分结果准确返回，未授权收费阶段前停止。
