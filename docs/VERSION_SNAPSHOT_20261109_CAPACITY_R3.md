本版保存已核验的 R3 容量规则、批次补位优先级及四处恢复边界修复。在原视频执行入口内核查本地占位；提交异常结束且无任务 ID、执行者已退出且无任务 ID、实际查询失败或来源不可核实的记录，按规则释放本地容量并保留原任务证据。正常排队和生成中的任务继续占位，找到新的活跃证据后恢复计数。业务结果与容量决定分开保存；释放不是取消远端任务，也不是授权再次付费生成。

共享容量保持最多 4 个当前已知有效生成占位、2 路下载。当前批次按冻结顺序持续补位，后来的批次不能挤掉它已取得的提交机会。若后续找回任务令已知占位超过 4，保留真实数量并停止新增，仍允许原任务查询和下载。不同故事的异常记录不再整项目阻断其他故事的合法工作。具体边界见 [R3 视频容量规则](VIDEO_CAPACITY_POLICY.md)。

本次四处补修：

1. 已保存的可信终态证据优先，旧 `running` 观察不能重新占位；中断后补齐容量记录，不反复扫描终态历史。
2. 找回有效回执时，在同一共享事务补齐任务 ID 与容量，避免 ID 已登记但漏算占位。旧成功回执不能推翻后来真实的查询失败。
3. 解释状态前核对 Job、Slot、回执与观察事件的身份。错误任务 ID 不污染原任务的 ID、状态或不可逆终态。
4. 不同集段的相同输入可以独立提交；同一集段同输入仍保留防重、原尝试复用及一次显式重试授权，不能通过新批次绕过。

保留三个 Skill 的同 ID 一次换图、原集段 ID 一次换提示词、`video run` 一次完成准备至交付、正确的 `reused` 标记、MiniMax-H3 内联 Context IR、旁白归属和图片流程。未新增用户执行步骤、独立清理命令、远端探测或付费重试次数。
