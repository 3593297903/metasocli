## P1：Windows 同一路径的大小写变化会使成功创建的回执无法保存

位置：`src/jobs/coordinator.ts:44`、`src/jobs/coordinator.ts:51`、`src/jobs/coordinator.ts:58`，以及 `src/jobs/submit.ts:78`。

登记项目时按忽略大小写比较根路径，但预留记录保留调用者传入的路径字符串，随后同步又用区分大小写的字符串比较。Windows 上这两种写法可以指向同一个实际目录。

已通过公开 `runCli(generate ... --submit-only)` 加假客户端复现：

1. 以包含 `CaseRoot` 的绝对路径登记故事到共享运行目录。
2. 以该路径的全小写形式生成同一故事的一个段。
3. 假接口收到一次 POST，正常返回 `fake-case-task`。
4. 保存回执前重新同步共享记录，因同一路径字符串大小写不同触发冲突。
5. CLI 退出1，报告 `RECEIPT_PERSISTENCE`；原 Job 变成 `submit_unknown`，磁盘任务没有 taskId。

这不是“未发出请求”：远端创建已经返回成功，只是客户端没有保存该 ID。真实环境中可能产生已经收费、却需要人工找回 ID 的任务。当前保护没有自动重发，不能把该问题描述为已经发生重复收费。

最小修复方向：统一故事根的规范身份和路径比较规则，登记、预留、同步、批次事件归属都使用同一规则；Windows 同目录大小写变化不能被当成另一个根。存量 ledger 的等价路径也要安全兼容，不能删除 ledger 或清空未知占位来绕过。增加公开 CLI 的大小写变体回归，断言一次 POST、回执持久化、原 ID 可恢复，另一真实目录的身份冲突仍被拒绝。

## P2：已全部完成项目被移动后，会阻塞其他项目的新提交

位置：`src/jobs/coordinator.ts:47`—`50`。

每次协调都无条件重新加载所有曾登记项目的原路径，未区分仍有活动/未知名额的项目与已完成且不占名额的项目，也没有安全注销或退休记录的路径。

已离线复现：

1. 故事 A 成功完成一个批次，成片通过验证，批次 `complete`，共享活动名额为0。
2. 将 A 的目录移动到同一隔离测试目录中的归档位置。
3. 创建全新的故事 B，使用相同运行目录执行批次。
4. B 尚未发送任何 POST，就因全局同步仍访问 A 的旧路径而返回 `NOT_INITIALIZED`。

影响：用户整理一个已完成项目，也会使同一运行目录下的其他项目无法生成；当前没有正式的安全移除登记办法。与仍有活动或未知任务的根目录丢失不同，这里已经确认 A 完成且名额归零。

最小修复方向：为已验证终态、没有未决生成名额的项目提供安全归档/退休机制，保留必要历史证据，使其不再强制依赖旧业务路径；兼容当前已有 ledger。仍有 reserved/submitting/queued/running/unknown 等未决任务时必须继续保守阻止释放，不能简单忽略所有缺失路径。补充“完成后归档不影响新项目”及“活动/未知项目丢失仍不能绕过额度”两组测试。
